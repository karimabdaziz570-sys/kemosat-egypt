# KemoSat Egypt — Production Starter v1.1

متجر عربي RTL لأجهزة البث الفضائي ومستلزماتها، مع Backend وقاعدة بيانات ولوحة إدارة.

## ما تم تجهيزه
- واجهة KemoSat Egypt Design 3 باللغة العربية.
- Node.js + Express.
- SQLite مع جداول المنتجات والعملاء والطلبات وبنود الطلبات والمديرين والجلسات.
- تسجيل دخول آمن للمدير باستخدام scrypt + جلسة Bearer قصيرة العمر.
- لوحة إدارة للطلبات والإحصائيات وإضافة المنتجات.
- API للمنتجات والطلبات.
- حساب شحن مبدئي حسب المحافظة.
- تجهيز Paymob Intention API مع Unified Checkout عند إدخال مفاتيح الحساب.
- إعدادات InstaPay والمحفظة كقنوات يدوية قابلة للإظهار في Checkout.

## التشغيل المحلي
1. ثبّت Node.js 20+.
2. انسخ `.env.example` إلى `.env`.
3. غيّر `ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SESSION_SECRET`.
4. شغّل `npm install`.
5. شغّل `npm run seed-products`.
6. شغّل `npm run seed-admin`.
7. شغّل `npm start`.
8. افتح `http://localhost:3000` والمتجر أو `/admin.html` للوحة التحكم.

## الدفع
Paymob يدعم في مصر مسار Intention API مع Unified Checkout. ضع المفاتيح في `.env` فقط، ولا تضع Secret Key في الواجهة. بعد تفعيل الحساب الحي، اختبر Sandbox أولًا ثم غيّر المفاتيح إلى Live.

**ملاحظة أمنية مهمة:** مسار webhook الموجود هو نقطة تجهيز فقط. قبل التشغيل التجاري يجب إضافة تحقق HMAC الفعلي وفق إعدادات حساب Paymob ثم اعتماد حالة الطلب على callback موثّق، وليس على بيانات غير موثقة.

## InstaPay والمحافظ
يمكن عرض بيانات InstaPay أو رقم المحفظة للتحويل اليدوي، لكن لا تعتبر الطلب مدفوعًا تلقائيًا من مجرد إدخال العميل للبيانات. يجب مراجعة التحويل أو استخدام بوابة/تكامل يدعم التحقق الآلي.

## النشر
- استضافة Node.js 20+ مع HTTPS.
- قاعدة بيانات دائمة (SQLite مناسبة لبداية صغيرة؛ PostgreSQL أفضل عند زيادة الحجم).
- ضع متغيرات البيئة في لوحة الاستضافة، وليس داخل Git.
- اربط `APP_URL` بالدومين النهائي.
- استخدم Reverse Proxy مثل Nginx أو منصة استضافة Node مُدارة.
- فعّل النسخ الاحتياطي لقاعدة البيانات.
- أنشئ حساب مدير فريدًا بكلمة مرور قوية.
- اختبر الطلب، الدفع، callback، المخزون، والشحن قبل فتح المتجر للجمهور.
